decisions:
  - choice: Keep reporters anonymous, verify them in private
    rejected: Show who reported each incident
    subtitle: privacy · internal identity check
    because: The map needs reports, and people only report if they are safe doing it. Every account is verified inside the app, so a report can be trusted while its author stays hidden from everyone else.
    cost: Identity verification has to be built and kept private; anonymity does not mean anyone can post.
  - choice: Validation by several people, no comments
    rejected: Comment threads on every report
    subtitle: scope · community validation
    because: Tranqui has one job, telling you what happened on your route. Several people confirming a report is enough; comments would turn a safety tool into a social network it does not need to be.
    cost: A report cannot carry a discussion, so its context has to fit in the report itself.
  - choice: Use browser-native controls
    rejected: A custom JavaScript menu and accordion
    subtitle: dialog + details
    because: A native dialog for the mobile menu and details for the FAQ behave the same across browsers, with keyboard and screen reader support built in.
    cost: Responsive styling, testing and a little JavaScript to open the menu are still needed.

### A visual that needed more context.

In the first landing mockups, the privacy and institutions sections used cropped interface fragments and decorative shapes. Feedback showed that the pieces did not make sense on their own. I replaced them with complete, readable panels and labelled the privacy preview as simulated. The plans section was also rebuilt with two equally tall cards.
