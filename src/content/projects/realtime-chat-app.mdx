## Problem

Wanted hands-on experience with WebSocket connection scaling beyond a single
process, without paying for a managed realtime platform.

## Constraints

- Single VPS budget — no managed pub/sub or hosted WebSocket service
- No managed pub/sub service
- Must survive a process restart without losing in-flight messages

## Decisions

**Redis pub/sub for cross-process message fan-out.** Rejected an in-memory
event emitter shared across a single Node process, because a single process
could not be restarted without downtime, and the VPS budget ruled out a
managed message broker.

**PostgreSQL for message history instead of a document store.** Rejected
MongoDB for flexible message schemas, because the message shape was fixed
and known upfront, and relational queries for conversation history were
simpler to reason about than document queries.

## Outcome

Sustained 500 concurrent connections on a single 2 vCPU instance with
sub-100ms message delivery, verified with a scripted load test.
